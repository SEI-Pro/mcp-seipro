## O que mudou

- **RFC 0010/0017 revogadas — validação de `protocolo_formatado` simplificada
  para regex fixo, sem descoberta nem keyring.** O problema real (o formato do
  número de processo varia entre instâncias SEI) é resolvido com dois regex
  conhecidos, tentados em sequência: SEI administrativo clássico
  (`^\d{4,6}\.\d{6}/\d{4}-\d{2}$`, ex: `50300.007186/2026-69`) e CNJ, usado
  pelo SEI de tribunais como o TJRO (`^\d{7}-\d{2}\.\d{4}\.\d\.\d{2}\.\d{4}$`,
  ex: `7002098-94.2026.8.22.0014`). Fallback permissivo obrigatório: uma
  string não vazia que não bata em nenhum dos dois formatos ainda é aceita —
  só entrada vazia é rejeitada.
- **Removidas** as tools `sei_detectar_formato_protocolo` e
  `sei_redefinir_formato_protocolo` — de ~28 tools que recebem
  `protocolo_formatado`, só 3 usavam essa validação, e a infraestrutura
  (keyring com `ThreadPoolExecutor`+timeout, cache global por host, `lru_cache`
  de regex, resolução de host via OAuth, 2 tools MCP inteiras) era
  desproporcional ao problema. Contagem de tools: 131 → 129.
- **`tools/configuracao.py` simplificado**: removida toda a infraestrutura de
  keyring/cache/`ThreadPoolExecutor`/`lru_cache` de descoberta de protocolo;
  `sei_cache_status`/`sei_cache_clear` (cache de catálogos, RFC 0019) não são
  afetados.
- **`processos.py`**: os 3 call sites (`sei_consultar_processo`,
  `sei_arvore_processo`, `sei_listar_documentos`) chamam a nova
  `_validar_protocolo(protocolo_formatado)` — síncrona, sem `ctx`.
- **Hint removido** de `hints.py` que sugeria chamar
  `sei_detectar_formato_protocolo` na primeira sessão.
- **`docs/rfc/0010-agent-protocol-discovery.md` e
  `docs/rfc/0017-lazy-protocolo-formatado.md` marcadas como Revogadas**,
  substituídas por este changelog.
