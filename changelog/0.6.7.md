## O que mudou

- **`todos setup` agora abre um wizard web por padrão** (mesmo espírito do
  `pink setup`, repo irmão): formulário local servido via `http.server` puro
  (sem dependências novas), com CSRF/host-check. `todos setup --cli` preserva
  o wizard de texto no terminal.
- Wizard web reusa a lógica de negócio já testada do CLI wizard
  (`setup_wizard.py`) — detecção de órgão/mod-wssei, leitura de config,
  montagem/deploy de config MCP — via dois adaptadores novos
  (`_validate_login`, `_save_password`) que trocam Rich console/`Confirm.ask`
  por retorno estruturado JSON.
- CSS (Pico v2) vendorizado localmente em vez de carregado de CDN externo —
  tela de credenciais não depende de rede/terceiros.
- `verify_ssl_disabled` conectado ponta a ponta: checkbox no formulário →
  `/api/detect-instance`/`/api/validate`/`/api/save` → detecção de
  órgão/mod-wssei — instâncias com certificado autoassinado agora são
  detectáveis pelo wizard web.
- Fallback automático para o wizard de terminal quando não há navegador
  utilizável (`webbrowser.get()` falha) — `--cli` continua funcionando como
  opt-in explícito, mas deixa de ser a única forma de configurar em ambiente
  sem browser (SSH, container).
- Cobertura de teste real do servidor HTTP (host-check, CSRF, rotas
  `/api/current-config`/`/api/save`/`/done`, guard de path traversal) — antes
  só os adaptadores tinham teste unitário.
