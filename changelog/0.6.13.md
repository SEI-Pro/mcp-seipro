## O que mudou

- **`sei_inspecionar_pagina`/`sei_submeter_form` genéricos (RFC 0020,
  protótipo)**: duas tools novas complementam as já existentes. `sei_inspecionar_pagina(url)`
  busca uma URL do SEI e devolve forms + ações descobertas (leitura pura,
  sem POST) — classificando cada `acao=X` por origem (`href`, `js_variable`,
  `js_function`). `sei_submeter_form(url_pagina, form_id, overrides,
  url_destino?)` submete um form com campos sobrescritos, com destino
  explícito opcional pro padrão JS "sobrescreve `form.action` antes de
  submeter o mesmo form auto-referente". Só o backend web implementa (não
  há equivalente REST). Ver `docs/rfc/0020-inspecao-e-submissao-generica-de-form.md`.
- **Fix (code review, BLOQUEADOR) — SSRF**: `url`/`url_pagina`/`url_destino`
  e o `action` resolvido do form chegavam ao cliente HTTP autenticado sem
  garantia de mesma origem. Novo `_validar_mesma_origem` (rejeita
  scheme+netloc diferente de `self.sei_root`) + `_enviar_mesma_origem`
  (segue redirect manualmente, validando origem em cada hop). Estendido
  também para `_post_form_preservando`/`_post_form_com_acao_override`
  (usados por ~10 métodos pré-existentes de bloco de assinatura/processo).
- **Fix (code review, BLOQUEADOR) — `<select>` sem `<option selected>`**:
  `_parse_form_info` (exibição) e `_coletar_estado_form` (o que é
  efetivamente enviado no POST) reportavam `""` nesse caso — HTML padrão
  trata a primeira opção como selecionada, não "nenhuma".
- **Fix (code review) — URLs relativas**: `_descobrir_acoes` e
  `_parse_form_info` agora recebem `base_url` e normalizam toda URL
  descoberta/action para absoluta.
- **Fix (code review) — `_next` removido de `sei_inspecionar_pagina`**: a
  sugestão de submeter o primeiro form encontrado foi removida — a camada
  genérica não distingue filtro/busca/paginação da ação desejada.
- **Fix (contagem de tools)**: corrigida a contagem de tools citada em
  README/CLAUDE.md/manifest.json/etc. de 129 para 131 — o RFC 0020 somava
  suas 2 tools novas a uma base de 127 desatualizada, colidindo
  silenciosamente com o 129 que a RFC 0019 (`v0.6.10`) já tinha estabelecido.
